An original Word document was provided by R. J. Early. Preparation involved the following steps:

1. The free translation was not always on its own line. This was fixed manually, the result being `Original/Paiwan Ch2.docx`. 

2. The scripts in the Jupyter notebook `script.ipynb` was then used to create the XMLs.

3. The character encodings from the original Word document did not transfer correctly, and no automatic solution was found. These were fixed using regular expressions (probably; unfortunately, the exact process was not recorded).

4. The following lines were fixed by hand:

story 061, sentence 034<br>
story 062, sentence 022<br>
story 071, sentence 064<br>
story 072, sentence 045<br>
story 074, sentence 070<br>
story 075, sentence 075<br>
story 095, sentence 008<br>
story 096, sentence 049<br>
story 097, sentence 022<br>

5. The QC script `clean_xml.py` was run, as per usual procedure. This mostly standardizes punctuation.

```bash
    python QC/cleaning/clean_xml.py --corpora_path Corpora/HundredPaiwanStories/XML
```

6. **Tag gloss translations with a language**

The morpheme-level (`M`) interlinear glosses were emitted as bare `<TRANSL>` elements with no `xml:lang`, which fails validator rule V023 (`xml:lang` is required on every `TRANSL`). The glosses are all English (English words plus Leipzig glossing abbreviations), so `xml:lang="eng"` was added to every such tag with:

```bash
    python Corpora/HundredPaiwanStories/CodeAndDocs/add_transl_lang.py
```

The script edits via targeted string replacement (leaving all other formatting intact) and re-parses each file with lxml to confirm the `TRANSL` count is unchanged and none remain without `xml:lang`. The sentence-level (`S`) free translations already carried `xml:lang="eng"` and were untouched.

7. **Split infix / reduplication morphemes**

The glosser packed actor-focus/perfective infixes and partial reduplication into a single `<M>` using `INFIX=ROOT` notation in *citation* form (e.g. `keman` → one `<M>` of `em=kan` / `af=eat`, where the surface is `k‹em›an`). `split_infix_morphemes.py` splits each such single-`M` word into two `<M>` elements — the infix/reduplicant (`-em-`, gloss `af`/`RED`) and the root with the infix position marked by `-` (`k-an`) — locating the infix by splicing it into the citation root to match the surface word (allowing one root-vowel syncope, e.g. `qetsi` → `q‹em›tsi`). The two new `<M>` carry only `FORM kindOf="original"` and `TRANSL`; their standard `FORM` and `PHON` are generated by steps 10–11.

```bash
    python Corpora/HundredPaiwanStories/CodeAndDocs/split_infix_morphemes.py
```

Cases that do not splice cleanly (consonant mutation, stacked `=`, an extra unglossed prefix) are written to `flagged_infix_splits.csv` for manual handling; `=` morphemes inside already-multi-`M` words — where the morpheme maps to an unknown *substring* of the word — are listed in `multi_M_eq_morphemes.csv` and handled in step 8.

8. **Split infix/reduplication morphemes inside multi-M words**

Step 7 only handled words whose `=` morpheme spanned the whole word. `split_multi_M_infix.py` handles the multi-M case: it peels off the sibling morphemes that match the surface directly to isolate the substring the `=` morpheme spans, then splices as in step 7 (e.g. `qemaqivu` with `<M>em=qa</M><M>qivu</M>` → peel `qivu` → span `qema` → `-em-` + `q-a`, leaving `qivu`). The `=` M becomes two Ms, the siblings are untouched, and the W's M ids are renumbered 0-based. Like step 7, the new Ms carry only original `FORM` and `TRANSL`; steps 10–11 fill the rest.

```bash
    python Corpora/HundredPaiwanStories/CodeAndDocs/split_multi_M_infix.py
```

477 morphemes split; words where a sibling doesn't match the surface (consonant mutation, infix vowel change, w/v alternation) or that stack multiple `=` morphemes are left untouched and listed in `multi_M_eq_morphemes.csv`.

9. **Capitalize the reduplication gloss**

An `<M>`-level `TRANSL` of exactly `red` is always the reduplication marker in this corpus (every instance is a reduplicant copying a sister morpheme; there is no colour-word `red`). `capitalize_red.py` rewrites these to the glossing abbreviation `RED`, leaving any word/sentence-level `red` untouched.

```bash
    python Corpora/HundredPaiwanStories/CodeAndDocs/capitalize_red.py
```

10. **Standardize the orthography**

The source uses Ferrell's orthography. `standardize.py` re-derives every standard `FORM` (S, W, and M tiers) from the original tier via the conversion table; capital-letter variants (`Ts → C`, `Ɫ → Lj`) are derived automatically from the table plus the `Orthographies/Ferrell/Paiwan.tsv` source profile.

```bash
    python QC/utilities/standardize.py --corpora_path Corpora/HundredPaiwanStories/XML --tsv_path Orthographies/ConversionTables/Paiwan_Ferrell_113.tsv
```

`standardize.py` writes a `standardize_warnings.csv` diagnostic into the XML directory — review it, then delete it (it is not part of the corpus).

11. **Add IPA**

```bash
    python QC/utilities/add_phonology.py --corpora_path Corpora/HundredPaiwanStories/XML --orthography Ferrell
```

The four texts with `dialect="unknown"` (`090`, `091`, `097`, `099`) fall back to the `default` column of both orthography tables, so **their IPA is provisional** and should be regenerated once a real dialect is assigned.

12. **Repair the `?`/glottal-stop conflation**

In Ferrell's orthography `?` is both the glottal-stop letter and question-mark punctuation, and `'` appears in the source only as a nested quotation mark; steps 10–11 map all of them blindly. `fix_ferrell.py` post-corrects both tiers, classifying every `?`/`'` from the original tier (see the script docstring). The primary signal is the English free translation: when a sentence's FORM and TRANSL contain the same number of `?` (ignoring the `(?)` uncertainty marker, and skipped if any morpheme carries `?`), every `?` in the sentence is a question mark. The remainder falls back to context rules (quote-adjacent or sentence-final `?` = punctuation) plus a corpus-attestation rule: a glottal stop is part of its word, so a word-final `?` whose bare form is attested elsewhere in the corpus without the `?` is a question mark (e.g. `matsay?` in `044S18` and `namaitazua?`/`liaw?` in `037S14` — all three words occur elsewhere with no glottal stop). Question marks are restored on the standard tier, and both `PHON` tiers are regenerated with the punctuation masked out, so no spurious `ʔ` remains. Residual ambiguous cases (a word-final `?` whose bare form is unattested, in a non-count-matched sentence) are kept as glottals and listed in `fix_ferrell_report.csv` for review.

```bash
    python Corpora/HundredPaiwanStories/CodeAndDocs/fix_ferrell.py
```

13. **Confirm glossing worked**

For now the glossing isn't standardized across corpora. But the following will at least check to make sure the glosses exist everywhere they are supposed to:

```bash
    python QC/validation/validate_glosses.py by_path --path Corpora/HundredPaiwanStories/XML --check_morpho
```

> Steps 5–13 are safe to re-run over the published `XML/`: the split steps (7–8) are no-ops once applied, and steps 10–12 fully re-derive the standard and PHON tiers from the original tier. (Earlier revisions of this pipeline used `fill_standard_tier.py` / `fill_phon_tier.py` to patch tiers without re-running steps 10–11; those scripts are gone — re-deriving is now the supported path.)

### Manual corrections (provenance only — not re-runnable scripts)

Two fixes were applied directly to the published data and are recorded here for completeness; they are one-off corrections, not part of the `.docx`→XML pipeline:

- **Word/morpheme desync repair (the `avanu` cascade).** The original glossing notebook split each tier on whitespace and zipped them positionally; the word `avanu` — glossed `avan nu` with an internal space — added an extra token that shifted every following morpheme onto the wrong word to the end of the sentence. Eight sentences (`030S6`, `039S12`, `039S14`, `044S4`, `050S52`, `052S17`, `063S4`, plus a separate one-off in `009S2`) were corrected by hand.
- **Duplicate M-id renumber.** Some hand-edits reused an `M0` id for two morphemes within a W; a 0-based renumber of the affected Ws restored unique ids. (`QC/utilities/fix_ids.py` does this, but it is 1-based whereas this corpus is 0-based, so it was done with a 0-based equivalent.)
- **`008S28` quotation repair.** The word glossed 'ah' read `'aa'` at S level but `'aa?` in its W/M tokens — the `?` was a stray closing quote, not a glottal stop (context, and the parallel `"aa,"` in `008S30`/`008S32`). Hand-edited to `"aa"` (W) / `aa` (M), double-quoted despite the nesting inside the larger quote: this corpus should not use single quotes for quotation marks, since `'` is reserved for the glottal stop in the standard orthography.
